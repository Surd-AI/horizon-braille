# Local ambiguity API

Run from the repository root with Node 22.13+ and installed project dependencies:

```sh
npm run start:api
```

This builds CommonJS server/core output under ignored `.local/api`, then uses Node's `--env-file-if-exists=.env.local` to load the ignored root server configuration. Existing process environment values take precedence. The server binds only `127.0.0.1`, port `8787` by default; an occupied port causes startup to fail without terminating any listener. No browser bundle, Vite `public` directory or frontend environment is involved. Never copy `SIMPLEX_API_TOKEN` into `VITE_*` variables.

Server environment:

- `SIMPLEX_API_TOKEN`: optional private token. Missing token leaves deterministic/manual work available with visible provider fallback.
- `HORIZON_API_PORT`: optional integer port, default 8787. Port 0 is useful for isolated tests.
- `HORIZON_UI_ORIGINS`: optional comma-separated explicit origins of the form `http://127.0.0.1:<port>`, default `http://127.0.0.1:5173`. No hostname aliases, paths, credentials, wildcards or non-loopback origins.

No requests are made on startup or health checks. Startup logs only the local address or a generic failure. No documents, model response bodies, headers or tokens are logged.

## Routes

Every route requires the exact `Host: 127.0.0.1:<actual API port>`. Any supplied Origin must be allowlisted. POST requires an explicit allowlisted Origin and `application/json` (optional UTF-8 charset); compressed bodies and extra unknown fields are rejected. Preflight allows only POST and Content-Type. JSON bodies are limited to 131072 bytes and source to 100000 UTF-16 code units. At most two conversions may be in flight.

- `GET /health`: `{ "configured": true | false, "userKeySupported": true | false }`. Origin may be absent for local CLI health probes. `userKeySupported` is false in public reverse-proxy mode.
- `POST /resolve`: `{source, options?, manual?, external?}`. `external:false` disables the provider. Returns `{decisions, ambiguities, encoded, conversion, status}`. `decisions` is the reusable `{documentSource,resolutions,fallbackCodes?}` object; `encoded` carries atoms and all diagnostics; `conversion` carries layout/exports. Status separates `semanticComplete`, `layoutComplete`, and `providerFallback`.
- `POST /convert`: `{source, decisions, options?}`. Reapplies existing decisions locally and lays out the result, with no provider call. The frontend should normally use `reflowExistingAtoms(encoded, publishingOptions)` for width-only changes; that avoids semantic encoding too.

Options accepted by JSON transport: `mode` (`document`, `text`, `math`, `chemistry`, `physics`), `columns`, `rows`, `paragraphIndent`, `strict`, `timePolicy`, independent boolean `recognizeMath`/`recognizeChemistry` (both default true), and `overrides` (existing Chinese word-boundary/readings overrides). Rich publishing profiles and function hooks remain local-core interfaces until separately given a JSON schema. `manual` has `{documentSource,resolutions}` with candidate IDs from the current source. Each ID must appear once. HTTP rejects duplicate IDs with 400, irrespective of order or source; local core conversion leaves duplicate decisions pending with `ambiguity-duplicate-resolution`. A manual edit must replace the existing unique entry. Supplying edits for different source text is visibly rejected as stale; original UTF-16 spans remain authoritative. No outbound URL, token, model or arbitrary prompt setting is accepted from the client.

## Meaning before encoding

Optional `POST /segment` accepts `{source, options?}` and returns `{documentSource, wordBoundaries, model}` without calling the disambiguation provider. `HORIZON_SEGMENT_URL` is a server-only loopback HTTP endpoint; it cannot be overridden by a request. JSON options also accept validated `wordBoundaries` and `chinese` (`tones`, `contractions`, `unknownSemanticTone`), shared with subsequent `/resolve` and `/convert`. See [segmentation limits and cancellation](../../docs/segmentation.md) and the [optional HanLP service](../segmenter/README.md). Model output remains a proposal and existing bounded word rules/manual precedence still apply.

`collectAmbiguities(string | EncodedDocument, options?)` extracts ASCII/fullwidth colon and actual Chinese multi-reading candidates, including Chinese in formula text and chemical conditions. Slash/minus/element are extensible kind names only; automatic extraction for those is not yet implemented. Manual word boundaries are separate from per-syllable choices. Human readings and bounds are retained; changing a candidate on an existing syllable does not split its word.

`resolveAmbiguities(source, {provider?,manual?,signal?,...convertOptions})` returns a source-bound resolution set. Explicit manual choices win. The standalone core uses checked local ratio/clock and word rules before asking an optional provider; conflicting cues, duration/minute-second and sports-score cues remain unknown. Bounded editorial exceptions resolve complete words 银行 (yin2 hang2), 通知 (tong1 zhi1), 会议 (hui4 yi4), and the checked plain-prose dispatch phrase 发通知 (fa1). These local heuristics are not a general dictionary confidence promotion; manual readings retain precedence. By default the core limits one pass to 64 questions. This API instead enables model-first processing for all non-manual questions in bounded batches (16 while streaming, 64 otherwise), subject to the request time budget. No automatic retry occurs on failure or unknown execution state.

`convertWithResolutions(source, decisions, options?)` returns an **EncodedDocument**, ready for `reflowExistingAtoms`. It rechecks candidate IDs, source identity and score validity. Valid non-unknown API choices are accepted at an inclusive confidence threshold of 0.5; the selected candidate probability is used only when explicit confidence is absent. A supplied distribution must still be complete, finite and normalized. The resolver and encoder share this threshold; local heuristic disagreement does not discard returned API choices. On fresh online passes, only source=manual takes human precedence; earlier API decisions may be replaced. Semantic adoption does not waive encoding scope, clock-range or unsupported-mapping diagnostics. `Resolution.source` distinguishes manual, heuristic and API decisions. Chinese `source` retains its dictionary/manual origin; `resolutionSource` records the decision separately. Only the resolved syllable's `CHINESE_POLYPHONY` diagnostic is removed.

The API keeps a bounded in-memory cache of validated model answers for 20 minutes (up to 512 question contexts per listener). Its key includes the question kind, bounded source context, exact target/word position and candidate list. Edits within that context or changes to candidates require a fresh model decision; edits elsewhere can reuse the answer. Manual choices still win. Failed, unknown and below-threshold answers are not cached. The cache is neither persisted nor included in the core npm package; a restarted process starts empty.

Fullwidth `：` follows the same candidate/range path without global NFKC or digit normalization; confirmed whole numeric ratios in plain prose use the mathematical expression encoder, without internal blanks or isolated-prose-symbol markers (GB/T 18028 §6.1.2.1). A ratio decision enables the existing checked mathematical colon encoder, including removing that exact math-colon ambiguity placeholder through a narrow semantic hook. A prose punctuation decision uses the existing Chinese colon cells. A bounded five-node single-letter mathematical mapping is supported; general mapping/type relations remain unsupported (see ../../docs/extended-colon-math.md). Non-prose punctuation/time expansion is deliberately unsupported so mathematical/chemical framing markers cannot be silently discarded.

`time` means **clock time hours:minutes**, not duration or sports score. Default `timePolicy:'normalize-hours-minutes'` supports complete plain-prose clock tokens with hours 0–23 and exactly two minute digits 00–59, e.g. `12:30` -> number/Chinese encoders for `12时30分`. Generated 时 maps to the original colon; generated 分 has a zero-width span at the original token end. A visible informational notice explains the expansion. Original document/source is never rewritten. The expansion inherits the Chinese tone options and stays in one layout group. Explicit `timePolicy:'preserve'` leaves cells unchanged with an unsupported-time diagnostic. This policy does not claim a verified clock-colon braille rule. Confirmed complete H:MM:SS clocks and explicitly identified durations are also supported; fractional tokens, malformed chains and non-prose time expansion remain incomplete. See [extended colon semantics](../../docs/extended-colon-math.md) for ranges and duration units.

Every unresolved ambiguity/failure is visible. Full standard support remains false; missing encoding/layout support is not promoted by a successful API call. Strict layout failure may return empty exports while retaining the document, atoms and diagnostics.

## Provider and cancellation

The server-only provider uses fixed `POST https://api.surdai.com/v1/systemone`, model `spx-cd-auto`, explicit `reasoning:false` (no `reasoning_max_tokens`), Bearer token, and `state` plus `questions[id] = {type:'choice',instructions,criteria}`. Only known `answers[id].choice` IDs can affect semantics. Responses are bounded to 131072 bytes while streaming; IDs, answer shape, probability keys, finite range and sum are checked before use. Question contexts are at most 128 UTF-16 units (extractor uses up to 48 on either side); candidates/descriptions and total request bytes are bounded before a token-bearing fetch. Redirects are rejected.

Default timeout is 15 seconds across headers and body; programmatic tests may supply 1–60000 ms. Request disconnect propagates AbortSignal to the provider. The UI still owns debouncing, latest-request invalidation, user cancellation and explicit retry controls. Reflow uses stored atoms and never re-resolves.

Tests use synthetic temp environment files and injected mock fetches. No live model test is part of CI. Official Node env-file behavior: https://nodejs.org/download/release/v22.13.1/docs/api/cli.html . The adapter implements the fixed provider contract in its source; mock tests do not establish current provider availability. No SDK/runtime dependency was added.

Reusable `fallbackCodes` is optional for backward compatibility. It contains at most 64 allowlisted provider/budget/answer-rejection code strings; output codes are deduplicated. Only fixed local failure codes and HTTP 4xx/5xx code forms are accepted, with no supplied messages, bodies, log text, or spans. `/convert` reconstructs safe local diagnostics and preserves `status.providerFallback` without calling the provider. Source edits invalidate this state along with decisions. Older DecisionSet objects without this field remain accepted, but cannot be claimed to preserve a failure cause they did not carry. Clear clock cues with an invalid time shape or range remain unknown; a model-selected ratio cannot override that conflict.

Literal text mode disables all formula delimiters, bare recognition and TeX escape interpretation while preserving original newline and paragraph controls. Unknown literal characters remain visibly diagnosed. The API transport now accepts mode text; old server processes must be rebuilt before requesting it online.

Each extracted ambiguity carries `contextTarget:{start,end,text}` relative to its short `context`, using UTF-16 half-open offsets. Target alignment, bounds and scalar boundaries are validated before fetching; missing/malformed targets fail closed. Original document spans remain unchanged. The model does not receive offset maps or need to count positions: each question directly marks the selected occurrence in its comma-delimited clause, with the complete bounded context on a separate supplementary line. Polyphone extraction also supplies optional `contextWord:{start,end,text}` from the existing ChineseWord span, only if the entire word fits inside the bounded context; this gives a marked target-word line before the clause. There is no new segmentation algorithm. Legacy structured callers may omit word focus; if supplied it must match the context, enclose the selected occurrence and respect scalar boundaries. This validates declared source alignment, not the linguistic correctness of caller-supplied segmentation.

The normal target delimiters are `【` and `】`. If either occurs in the original context, the provider chooses the first numbered pair `⟦目标N⟧` / `⟦/目标N⟧` absent from that context. Source strings are JSON-escaped so quotes, backslashes and newlines cannot create new instruction lines. The concise Chinese instructions identify only the marked occurrence, treat source as data, and request unknown for uncertainty/conflict. Criteria retain the original candidate IDs; Mandarin readings display standard tone marks using the existing pinyin library, without invented dictionary meanings or sample-specific examples. Serialization and validation do not guarantee that a model obeys the prompt.

A source-based `/resolve` caller needs no new fields. The unchanged 128-unit context and total 131072-byte request caps still apply, including prompt/marker overhead; each API batch is validated independently and an oversized batch fails closed without retrying. No confidence, grammar, cancellation or whitelist guard was weakened.

Local colon grammar uses the target's comma-delimited clause while the model retains the broader bounded sentence context. Thus `时间12:30，比例3:2` resolves independently; `时间：12:30，比例：3:2` distinguishes label punctuation from numeric colons. Invalid clocks, multi-part times, durations, scores and conflicting cues in one clause remain pending. The standalone resolver can finish checked cases locally; the API's model-first setting asks about non-manual cases unless a validated cached answer is available. Model assistance selects meanings/readings from supplied candidates and does not certify national-standard encoding rules. No retries or new slash/minus/element extraction were introduced.

The standalone editor runs at `http://127.0.0.1:5173` via `npm run dev`; start this loopback server separately with `npm run start:api`. The editor now checks the local server and, when a server token is configured or a user enters a SurdAI API Key, automatically sends ambiguity decisions after input settles. The user Key is held only in page memory and sent only to the loopback server as `X-SurdAI-Key`; it is never persisted or placed in a browser build. Direct browser calls to SurdAI are blocked by the provider's CORS policy. The loopback launcher permits a user Key only for `/resolve` from an allowed `http://127.0.0.1:<port>` origin, validates its shape, and creates a request-scoped provider without sharing the server decision cache between Keys. Production reverse-proxy mode disables this header entirely and continues to use only the server token. If the local service is absent, the editor labels its output as an offline preview. This local service is not a public API deployment.
